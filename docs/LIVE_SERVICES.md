# 本机插件、peer、搜索和生图实服务验证

2026-11-13，使用 aigf-manager 虚拟环境和运行副本，除聊天平台外采用实际驱动、HTTP、模型及服务接口。两个隔离的 NoneBot 实例同时运行，分别接入外部 OneBot WebSocket 模拟器；不复用现有 bot 端口、peer token 或数据目录。

## 最终结果

用户更新 `.env.dev` 后重新读取配置，最终 16 项检查全部通过，没有阻塞服务或未完成案例。

| 路径 | 实际验证 |
| --- | --- |
| 本机调用 | 模型调用 invoke_plugin，复制实际用户事件命中 echo matcher，插件经原生 OneBot API 输出；只投递一次 |
| peer 双 bot | 启动实际 peer 插件，校验鉴权和白名单；命令清单经 /peer/capture 返回；invoke_peer_plugin 经 /peer/invoke 执行远端 echo，再由捕获 HTTP 将结果回传到本体聊天上下文 |
| 搜索 | 新配置 DeepSeek 搜索工具成功，独立生产客户端查询得到 2 条带有效 URL 的结果；备用 OpenWebSearch 临时 daemon 也返回 2 条结果 |
| 后台生图 | MiniMax-H3-Image 实服务生成一张 2560×2560 图片；外部模拟平台接收原生图片段并解码，Pillow 校验通过，人工查看符合白底蓝色圆形要求 |
| 异步会话固定 | 生图期间给另一会话发消息，图片仍发回创建任务的会话；只创建一个任务、发出一张图 |
| 结束清理 | 本体和 peer 正常关闭，连接与测试子进程已回收 |

peer 产品协议仍只确认 accepted，不提供通用的执行完成证明或请求/输出关联。本案例通过实际命中的测试命令输出和本体收到的回传分别验证执行与回传，不能把所有 accepted 回执升级为执行成功。

本机和 peer 命令测试使用 echo，不代表 rollpig 等其它插件的所有业务功能已逐一验证。未改变默认协议、真实会话配置或发布状态。

## 联调发现并修复的问题

1. 搜索异常原先返回空列表，工具会把 HTTP 403 当作搜索完成。增加兼容列表接口的逐请求失败元信息；HTTP/服务异常返回 failed，正常空结果仍为 ok。旧协议的格式化提示同样说明服务失败。状态随每次返回值携带，避免并发会话共享错误状态。
2. 本体与 peer 的捕获钩子原先在确认消息体之前解析会话；查询成员/群资料时可重入同一钩子。将消息体检查前置，无消息体的 API 不进入会话解析。修复后双实例实际链路恢复，并增加两侧回归用例。

原 Bocha 返回 HTTP 403，响应明确指出余额或套餐配额不足；原生图配置返回 HTTP 404/UnsupportedModel。由用户更换配置后成功，未由测试脚本充值或切换计费端点。历史失败和测试观察器误用 ContextBus 导致的一次超时均保留，不覆盖为成功。

## 复跑

在 aigf-manager 根目录：

```powershell
.\.venv\Scripts\python.exe ..\nonebot-plugin-aigf-master\tools\run_service_checks.py --workspace . --env-file .env.dev --live
```

默认依次测试 routing、search、image。可用 `--checks routing`、`--checks search` 或 `--checks image` 选择重点；各模式仍先启动本体/peer，并验证命令清单推送。真实模型、搜索和生图会产生相应服务费用。每次新建隔离目录；凭据通过 stdin 传入子进程，不写入命令行或报告。

本轮不属于默认离线测试集。健康和关闭接口只由测试入口提供，要求临时 token；业务插件没有增加测试接口。真实聊天平台、所有替代服务后端、图生图/平台图片下载的全部实服务组合，以及连续 24 小时观察仍不在本轮结果内。
